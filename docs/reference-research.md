## 2. 逐个来源：它做了什么、好在哪、UU889 怎么借

### 2.1 Drama Skills（zenstory-ai，MIT）——最完整的「短剧剧作 + 提示词」方法论

**是什么**：12 个 Agent skill，覆盖 原著分析 → 分集剧本 → 视觉设定 → 图片提示词与分镜 → 视频提示词 → 确认后生产 → 剪辑成片 → 审查，外加对标拆解。作者自述来自上千个 AI 短剧 / 漫剧项目，原先近 8 万行的自建工具「在模型迭代速度面前维护不动」，于是蒸馏成文档 + 检查脚本。样片：20 章原著改编，第 1 集 68 秒竖屏、20 镜，视频成本约 40 元。

**创作思路与优点（逐条）**

1. **五份 Markdown 分管五层事实**：`剧本.md`（发生了什么）/`视觉设定.md`（造型、地点、道具、连续性锁）/`分镜.md`（镜头职责、起止、冻结关键帧）/`图片提示词.md`/`视频提示词.md`，剪辑时加 `剪辑单.md`。同一个镜头在四份文档里各管一层，互相引用 ID（`SHOT-EP001-002`、`IMG-*`、`MOTION-*`）。
2. **用可核对的文件事实约束一致性**：检查脚本核对文档之间的引用——分镜关键帧写到某个人物，「视觉依据」里必须有他；分镜 2 秒、视频提示词写 3 秒会报错；视频提示词里四字以上的引号台词必须逐字来自剧本。
3. **连续性锁**：`LOCK-JIANGCHEN-DRESS《江晨松枝绿常服》· 锁面：pine-green lapel service jacket`，生效镜头列表 + 锁面短语，冻结关键帧和视频提示词里原样出现。
4. **冻结关键帧只投影起点**：删掉终点才出现的文字、动作和道具状态；需要时另写「收尾关键帧」对称地投影终点。
5. **起点 → 唯一动作 → 终点**：每镜唯一职责；数一下这一镜要观众看清几件事，按镜长判断放不放得下——「视频模型不会删掉多出来的动作，而是把它们压到看不清」。
6. **运镜逐镜选，固定也要写理由**；对白场有默认覆盖切法；镜长由声音事件推出，不按剧本字数折算。
7. **场景站位先写锚点和关系**：一场戏拍多镜时，开头写「场景站位」——固定锚点、各人相对锚点的位置、轴线与 working side、哪一镜改变站位。
8. **参考图三种状态**：`REF-*`（项目里真实存在、检查过的图）、`PLAN-*`（创作者会在自己工具里挂的图，照常写图生视频提示词）、「待补参考图」；**点名模型 ≠ 选择文生视频**，缺图默认写挂图计划而不是降级。
9. **参考槽位格式**：`REF-<slot>（顺序：n）· 路径《中文名》（用途：…；控制：…；不得控制：…）`，用途九选一：身份 / 造型状态 / 地理 / 构图 / 尺度 / 效果 / 起始帧 / 结束帧 / 风格；一张图只占一个槽位；一镜最多一张起始帧一张结束帧。
10. **槽位不够时的取舍顺序**：起始帧、正在说话或做主要动作的人物、必须认得出的道具、地点、其余入画人物、定调图。
11. **同一集像同一部片**：每条关键帧用同一句画风、每个场景同一句光与色温；先出该场景一张中远景作「定调图」，其余镜头把它作为最后一张参考、只取色调光线质感不取构图。
12. **近景挂地点板会被拉宽**：近景类关键帧挂地点板常被拉成中远景，这时写具体取景，仍偏宽就不挂地点板、背景写进正文。
13. **续接链**：同一连续时空相邻段默认「从上一段生成结果续接」，第二段起同时绑定上一段**实际视频**和**实际尾帧**；两段之间是剪接（换景别 / 正反打）就不进同一条链。
14. **视频提示词默认不生成字幕**：正文直接写明「任何时刻都不生成非画内字幕、caption 和对白文字叠加」；画内需要可读的文字逐字写明字符、语言、承载面和位置。
15. **对白估时**：H3 中文小样本约 4.1 个可发声字/秒，太密会赶词或静默截断；口型落错人时，在说话人第一次出现时交代画内 / 画外与音色，台词紧跟他的动作句，画里其他正脸写明闭嘴。
16. **先预览、确认，再生产**：生产 skill 展示本次准确数量、内容、参考、参数、输出和 adapter，明确确认后才调用外部接口；供应商凭据不进项目；提交后拿到任务 ID 就落盘，中断用 `audit` 找 `orphaned_provider_job`、`collect` 取回，不重投。
17. **剪辑单写理由**：逐段写入点、出点为什么选在那里；字幕逐字取自剧本；统一响度；「未采用镜头」逐个写镜号和理由。

### 2.2 说好 skills（eternityspring，Apache-2.0）——「确定性质量门」与小说改编流水线

**是什么**：7 个 skill：novel-outline（改编大纲五件套）、novel-characters（角色圣经）、character-refs（真出角色参考图）、novel-art（场景 + 道具美术圣经）、novel-script（剧本）、novel-staging（开场站位）、novel-storyboard（分镜 + H3 提示词）。全部用零依赖 Node 脚本做校验和 HTML 报告，模型只写内容。

**创作思路与优点**

1. **质量门全部是代码**：大纲 14 道、剧本 10 道、分镜 18 道，每道都有击穿用例（自测 249 / 154 / 336 项断言）。门失败会追加到 `.gates.jsonl`，`stats` 回答「哪道门最常响（那条规则模型最常无视，该改措辞）、哪道门从没响过（死门或已内化）」。
2. **大纲五件套**：改编说明、人物表、爽点表、分集梗概、资产清单——「四件模型写、一件脚本算」，资产清单从分集数据汇总，「模型手写必漏」。
3. **大纲门**：主角组 1–5 人、重要配角 ≤10、功能性角色 ≤10；主场景上限 = 4 + ⌈集数/10⌉（夹在 5–15，60 集 → 10），「场景是生成的，没有搭景钱，放宽换观赏性」；叙事道具 ≤8 件；一次性场景要有规避方案；爽点间隔 ≤3 集；第 1 集有钩子；大爆点不压最后一集；每集三栏齐全；三人同框要有拆解；生成难点进预警。
4. **只问两件必问**：总集数 × 单集时长、题材（决定爽点类型，猜错整份废）；改编幅度默认「抽核」（忠实 / 抽核 / 借壳）；**禁止凭书名脑补内容**，关键取舍附原文逐字 evidence。
5. **快版骨架先拍板**：「砍了哪条线、合了哪些人、大爆点落在第几集」三件事给用户确认，不点头不写分集。
6. **长篇分卷摘要**：每卷 15 章，子代理并发，截断要明说。
7. **剧本「剧本管戏，分镜管拍」**：剧本只有集、场次、节拍流（动作节拍 ⇄ 台词行交替），每句台词是结构化条目（说话人 + 台词 + 语气），直接对接 TTS。
8. **剧本门**：每集时长在目标 ±15%（台词 4.5 字/秒、动作 2.5 秒/拍）、单句 ≤35 字、说话人在本场或标 VO、钩子在全集前 3 拍内兑现（冷开场）、每场至少一个动作节拍（「纯对白的场是广播剧」）、爽点认领、场景 / 光照 / 道具对账美术圣经。
9. **动作节拍只写常见动作**：「挑担上船、搭手卸担」AI 见过千万次；「伸篙一挡、睫毛颤」这种精巧动作生成必崩。
10. **台词本**：按角色聚合台词，组头带音色提示词按钮——台词和音色一页。
11. **分镜三层**：段（一次视频生成 ≤15 秒）→ 切（段内 2–5 秒，认领剧本节拍）→ 分镜图（主分镜图钉 0.00 秒，子分镜图钉各自切点）；镜头不跨场次；每个节拍被恰好一个镜头认领；同框 ≤3 人。
12. **构图量化字段**：每段 `blocking`（谁在左谁在右、间距），每切焦距 / 机位 / 构图 / 视线落点 / 焦点 / 稳定性——不出分镜图时它们就是构图的全部来源。
13. **生成批次单**：同场景 + 同光照的镜头归一批，共用同一张环境参考图（AI 版顺场表）；**配音对齐单**：每句台词对到镜号。
14. **分镜图提示词直呼角色名，镜头正文用通用身份**；出图提示词禁止人名（会被画成文字或混淆）。
15. **角色参考图一个根**（见 0 节 #10–#11）；只有年龄、性别、年代推不出来要问，其余自己补并标 `stated / inferred / default`；服装分上下装（大头照只用上装，带下装镜头会被拉远）；冻结三样：锚点 sha256、画风快照、文字描述指纹，任一变化依赖图标过期。
16. **模型不锁定**：一致性来自同一张锚点而不是同一个模型（Qwen 锚点 + GPT 派生可以）。
17. **开场站位报告**：可拖拽俯视图、8 道门、导出一句开场站位进分镜第一段。

**UU889 怎么借**：#3/#8 做成「剧本检查」（catalog skill `episode-script-craft` + 工作流 `novel-to-drama` 的检查步骤）；#5 做成工作流里的确认点；#9 写进 storyboard-breaker 与「可生成性」skill；#11–#13 与 UU889 现有「分镜段落 + 子镜头」高度一致，可补「生成批次单 / 配音对齐单」两个视图；#15–#16 改进角色出图。

### 2.3 Toonflow（HBAI-Ltd，MIT）——无限画布 + 导演执行内核

**是什么**：开源 AI 短剧 / 漫剧平台，Bun + Vue 3 + Electrobun，桌面 / Android / Docker；无限画布组织剧本、角色、场景、视频片段；节点（文本、图片、视频、音频、生成节点、3D 导演台、逐帧拉片）、工具（askUser、assetOperator、canvas、ffmpeg、sandbox、skillOperator、webFetch、webSearch）、团队（storyboardTeam：director / writer / reviewer）、MCP、插件市场、A2A。示例：2 小时出 2 分钟成片，Seedance 2.0 + GPT Image 2 + Claude Opus，约 ¥130（视频 ¥120）。

**创作思路与优点**

1. **Seedance 路由锁存**：已有定稿剧本 + 意图是做视频，就自动进入 Seedance 执行态；用户没说 2.0 还是 2.5 只问一次；用户只回「16:9」「1080p」也视为当前任务的配置补充，不解除锁存。
2. **阶段硬隔离**：进入视频提示词阶段后只用一套导演规则，不再混读其它分镜方法，避免两套规则打架。
3. **剧情保真锁（A0.1）**：「只导演，不编剧」。可以拆分、合段、计时、镜头化、站位化、把已有动作写得可见；不可以新增 / 删除 / 替换 / 改归属 / 改顺序；剧情事实来源优先级：用户最新指令 > 原始剧本 > 用户资产设定 > AI 之前生成的内容；**具体化边界**：删掉这条描述剧情事实完全不变才允许（「道具接触掌心擦过手指」可以，「打开容器取出新道具再擦」不行）。
4. **全片先规划再分批交付**：长剧情先建「全片段表」，分批只是交付容量管理，每批保留全局段号；原始时间码默认是参考节奏不是生成段。
5. **画面文字分两类**：后期字幕 / 标题 vs 场景内实体文字。
6. **源剧情账本**：原子节拍全部保留，五类关键标签只标重要性不改顺序，每个节拍先做时间预算。
7. **理论最少段数 vs 实际段数**：不为了段数最少牺牲自然对白、动作过程或反应时间。
8. **站位双层坐标**：世界坐标 + 画面坐标，每段自包含 5 块信息；连续场景状态链；人物移动只服从源剧情，不为连续性补动作；轴线规则；换场重新锚定。
9. **表演层**：情绪 = 行为的副产品；目标指向对象；微表情要有源剧情依据和触发；mask + crack（压抑后裂开）；克制型爆发；反应与台词的相对时机；微表情事件数是上限参考不是配额。
10. **运镜跟情绪曲线**；段间衔接「独立生成优先」；动作连续剪辑。
11. **跨段连续性先判关联再校验**：人物位置、道具状态链（段内 + 跨段）、场景与物理环境。
12. **3D 导演台**：用文字生成场景、低多边形关节人偶动画与运镜，三维取景记录关键帧，导出 PNG / MP4 作动作和镜头预演。
13. **逐帧拉片**：见 0 节 #17；AI 辅助拉片可填 ≤2000 字分析重点（构图、调度、运镜、剪辑节奏）。
14. **团队智能体**：导演统筹、编剧写、审阅者审；成员结果是待核验材料不是用户指令；不能递归互相委派；未生成素材时不评价画质口型。
15. **开放生态**：插件市场、MCP、A2A、21 种界面语言。

**UU889 怎么借**：#3 是最该补进 UU889 的规则（catalog skill `plot-fidelity-lock`，挂到 storyboard 和视频提示词两个智能体）；#4–#7 对应长集分批；#8–#11 补进分镜 skill；#12–#13 是「工作流」板块的高级节点候选；#14 对应「智能体」板块的多角色协作（导演 / 编剧 / 审阅）。

### 2.4 seedance2-skill（dexhunter，MIT）——Seedance 2.0 写法大全

- **输入限制**：图片 ≤9、视频 ≤3（总 2–15 秒）、音频 ≤3（总 ≤15 秒）、总文件 ≤12；输出 4–15 秒、480p–720p；不支持写实真人脸素材。
- **@ 引用 + 用途**：`@图片1 作为首帧`、`参考 @视频1 的运镜`、`背景BGM参考 @音频1`、`字体参考 @图片2 的字体`……**每个素材都要说清用途**，「只写参考@视频1」是常见错误。
- **公式**：主体 + 场景 + 动作 + 运镜 + 分时段 + 转场特效 + 音频 + 风格；10 秒以上用分时段（0–3 秒 / 3–6 秒…）。
- **12 种场景模式**：人物一致性、运镜复刻、特效复刻、视频延长（向后 / 向前，生成时长选新增部分）、视频编辑（改剧情、换角色、加元素）、音乐卡点、对话演绎、一镜到底、电商、科普、**AI 短剧 / 漫改**（「将 @图1 以从左到右从上到下的顺序进行漫画演绎，保持台词与图片一致」）、视频融合。
- **短剧片段模板**：画面（0–5 秒）+ 台词 1（角色 A，哽咽怒吼）+ 画面 + 台词 2 + 画面 + 音效 + 「精准 15 秒，无冗余」。
- **避坑**：引用模糊、指令冲突（同段固定镜头 + 环绕镜头）、内容过载、素材无归属、忽视音频、时长不匹配。

### 2.5 MiniMax H3 Max 提示词库（h3max.io，MIT）

### 2.6 claude-animated-shorts（mromidev，MIT）——「2D 角色放进 3D 世界」

### 2.7 chengfeng-videocut-skills（Apache-2.0）——口播剪辑的「账本」思想

- 七个入口：剪口播、字幕、画面、导出、上报 Bug、检查更新、工作台操作。
- **剪口播**：云端逐词转录 → 词典修字出修字表 → 五轮扫描（每轮只找一类口误 / 重复）→ 删词汇总表 + 重复句子表 → Studio 人工复核 → 复盘沉淀偏好与词典。**不切媒体**：「账本改一次几十毫秒，切一次是不可撤销的文件」。
- **用户只在三处说话**：继续还是重来、Studio 复核、完成确认；其余单向汇报。每步的完成判据是产出物。
- **字幕**：「剪口播说了算留哪些话在什么时候；字幕说了算屏幕上显示什么字」；一屏字幕存词 id 列表 + 显示文字，**不存秒数**，失效能精确到「第 7、第 12 屏的词被剪掉了」；不需要重新转录。
- **画面**：层绑字幕屏不绑秒数；四步：文字定任务 → 抽 8–12 帧真的看（实测 12 段里 2 段被画面推翻）→ 量运动窗口（相邻帧像素差，层只盖稳定窗口、在画面开始动前 0.2 秒退场）→ 做层放层；「画面自身足够清楚 → 不动，是最常见的正确答案」。
- **事故簿**：规矩在正文，故事在另一个文件。

**UU889 怎么借**：字幕「存词不存秒」很适合 UU889 字幕和剪辑（镜头增删后字幕自动跟着走）；「事故簿」做法可用在 skill 维护（CLAUDE.md 已在做类似的事）。

### 2.8 video-use（browser-use，MIT）——「读视频，不看视频」

- LLM 不逐帧看视频：第一层是词级转录（含说话人、笑声掌声叹气等音频事件），所有素材打包成约 12KB 文本；第二层是按需的「胶片条 + 波形 + 词标签」合成图，只在决策点调用。「朴素做法 3 万帧 × 1500 token = 4500 万 token 噪声」。
- 流程：转录 → 打包 → LLM 推理 → EDL → 渲染 → 自评（每个切点 ±1.5s 抽图查跳帧、爆音、被遮字幕），有问题修了再渲染（最多 3 次）。

- 先用 4–8 句话提策略、等确认；会话记忆写进 `project.md`，下次接着做。
- 动画叠层用并行子代理，每个动画一个。

**UU889 怎么借**：`ffmpeg-merge.ts` 补 30ms 淡入淡出、字幕最后叠、成片切点自检；智能体板块的「剪辑师」模板直接用这套原则。

### 2.20 OpenAI 内容溯源（verify / advancing content provenance）

## 3. 横向综合：按 UU889 的制作环节归纳

### 3.1 小说 → 分集（改编）
- 只问两件必问（集数 × 时长、题材），其余默认 + 告知；禁止凭书名脑补，关键取舍附原文证据。（shuohao）
- 长篇先做「抽样快评：值不值得拆」，再全量拆；章节数不直接当集数。（drama-skills novel-analyze）
- 五件套 + 质量门 + 快版骨架拍板。（shuohao）
- 每集：进入状态、目标、转折、回报、交接事实；钩子 + 悬念必填。（drama-skills / shuohao）

### 3.2 剧本
- 剧本管戏，分镜管拍；台词结构化（说话人 + 台词 + 语气）。
- 冷开场：钩子在前 3 拍（或项目档案的 `first_hook_seconds` 秒内）兑现。
- 每场改变一样东西；纯对白场不行；动作只写常见动作。
- 单句 ≤35 字、按 4.5 字/秒估时；目标时长 ±15%。
- 「能演的不说」；去 AI 味是定点修订，不抹平作者个性。

### 3.3 资产（角色 / 场景 / 道具）
- 角色：一个锚点根 + 派生视图；大头照必出；服装分上下装；出图提示词英文、不写人名、不写画风词（画风由项目统一附加）。
- 人物差异要可枚举（脸型、瞳孔高光形状、固定配件），防全剧趋同。
- 场景：白板图（无人无手）、光照状态变体、尺度参考；主场景数量随集数给上限。
- 道具：叙事道具 ≤8 件、状态变体（新 / 破 / 染血）、持有人。
- 连续性锁：锁面短语逐字进提示词。

### 3.4 分镜
- 段 ≤15 秒 / 切 2–5 秒 / 段不跨场；节拍认领；同框 ≤3 人。
- 起点 → 唯一动作 → 终点；冻结关键帧只投影起点；可选收尾关键帧。
- 场景站位（锚点、相对位置、轴线、working side）。
- 参考图槽位带用途；缺图写挂图计划不降级；按代价取舍。
- 定调图：每个场景先出一张中远景，后续镜头只取其色调光线质感。
- 电影语法：建立镜头开场、不连续两个特写硬切、切镜必须带来信息 / 权力 / 情绪 / 空间 / 节奏变化。

### 3.5 视频提示词
- 按目标模型方言（Seedance 2.0 / 2.5、MiniMax H3、Wan、Grok、Veo…）。
- 剧情保真锁；正文不写占位符、路径、QA 结论。
- 声音写成完整时间线（逐字台词只出现一次）；无对白镜写底声或静默；默认不生成字幕。
- 物理：接触、受力、支撑面、重心转移、落地；动作特效「蓄力 → 释放 → 接触 → 恢复」。
- 续接：同一连续时空相邻段绑定上一段实际视频 + 实际尾帧。

### 3.6 生产与成本
- 预览 → 确认 → 提交；费用预估；任务 ID 立即落盘；中断先找回不重投。
- 迭代只改一个变量，记录第一个可见失败。
- 抽卡比例高（Hell Grind 64:1），多版本保留与快速挑选是刚需。

### 3.7 配音、配乐、字幕
- 旁白按句合成拿时间轴，按配音真实时长定镜头。
- 口型取舍：正面说话镜用视频模型同期人声，其余用 TTS。
- 字幕逐字取自剧本；存词不存秒；字幕质检规则（长行拆分、标点、填充词、幻觉、密度、最短时长）。
- 响度统一（-14 LUFS 类）；配乐在说话时闪避。

### 3.8 剪辑与成片
- 入出点写理由；未采用镜头写理由。
- 30ms 音频淡入淡出；字幕最后叠；切点吸附词边界；逐段抽取后无损拼接；切点自检。
- 导出剪映草稿、台词长图、内容溯源标注。

### 3.9 对标、拉片、复盘
- 参考视频 → 拉片（切点、关键帧、原音轨）→ 测量（集长、镜长、对白密度、开场、集尾）→ 机制候选 → 节奏档案 → 差距对照 → 出片验证。
- 质量门失败计数：最常响的门 = 最该改措辞的规则。

### 3.10 产品形态与架构
- 无限画布（Toonflow）、看板 / 审批门 / 回放（OpenMontage Backlot）、对话智能体（uu889-video）、确定性检查脚本 + HTML 报告（shuohao）、skill 可在线编辑（UU889 已有）。
- 插件 / MCP / A2A 开放；团队智能体（导演 / 编剧 / 审阅）。

## 4. 对「一键生成 / 智能体 / 工作流」三个板块的建议

| 板块 | 建议 | catalog 里对应的数据 |
|---|---|---|
| 一键生成 | 视觉风格从 8 个扩到 30+，每个风格带「制作形态」标签和一句「身份锚点 / 运动预算」说明，帮助用户选对形态；新增「解说 / 知识类」入口（不需要角色一致性） | `catalog/styles/*.json`（30 个） |
| 智能体 | 按岗位给 14 个模板：小说改编策划、短剧编剧、角色美术、场景道具美术、分镜导演、Seedance 提示词师、MiniMax H3 提示词师、配音导演、剪辑师、对标拆解分析师、审片质检、解说短视频编导、趣闻动画编导、宣发运营；每个模板挂相关 skill | `catalog/agents/*/AGENT.md` + `catalog/skills/*/SKILL.md`（22 个 skill） |
| 工作流 | 12 个模板：小说改编分集、一句话创意到第一集、剧本到分镜与提示词、对标拆解到节奏档案、角色设定包、场景美术包、主题解说视频、真实趣闻动画短片、参考视频翻拍方案、宣发文案包、剧本体检、漫画分格转动态漫 | `catalog/workflows/*.json` |

catalog 的格式按「三板块」线程约定：
- `styles/<id>.json`：`id / name / prompt / description / tags / source{name,url}`
- `skills/<id>/SKILL.md`：frontmatter `name / description / source / source_url`
- `agents/<id>/AGENT.md`：frontmatter `name / description / category / skills / starters / source / source_url`，正文为系统提示词
- `workflows/<id>.json`：`id / name / description / category / tags / source / inputs / steps / handoff`
