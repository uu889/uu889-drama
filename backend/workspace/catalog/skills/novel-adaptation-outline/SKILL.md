# 小说改编大纲

把一本小说（或长篇连载、多集散稿）改成可分集制作的短剧大纲。**四件模型写，一件脚本算**：改编说明、人物表、爽点表、分集梗概由你写；资产清单从分集数据汇总，不要手写（手写必漏）。

## 开工前只问两件事

一次问完，不轮流盘问：

| 参数 | 处理 |
|---|---|
| 总集数 × 单集时长 | **必问**，没有合理默认 |
| 题材 | **必问**，决定爽点类型，猜错整份废 |
| 改编幅度 | 默认「抽核」（忠实 / 抽核 / 借壳），告知即可 |
| 已有偏好 | 默认无（想保哪个角色、哪场戏） |

**禁止凭书名脑补内容**，一切判断基于给到的原文。关键取舍附原文逐字片段作为依据。章节数不直接当集数。

## 长篇先快评

原文很长时，先抽样读开头、中段、关键转折，给出「值不值得改、最强的卖点、最大的改编风险、建议集数」，再决定是否全量拆。全量拆时按约 15 章一卷做卷摘要，读不完的部分要明说「尾部没读到」，不静默截断。

## 第一步：快版骨架 → 用户拍板

先只写四块：改编说明、人物表、场景表、爽点表。然后把三件事摆给用户确认：

1. **砍了哪条线**；
2. **合了哪些人**；
3. **大爆点落在第几集**。

用户不点头不写分集。快版错了只损失一轮骨架，分集写完才发现方向错，全废。

## 第二步：分集梗概

每集写三栏：**开场钩子 / 本集剧情（叙述体，不写引号对白）/ 结尾悬念**，并标注本集认领的爽点。每批 ≤10 集；写后一批时带上前一集的结尾悬念，保证接得上。

## 质量门（逐条自查，不通过就改）

- 主角组 1–5 人；重要配角 ≤10；功能性角色 ≤10；
- 主场景数 ≤ 4 + ⌈集数 ÷ 10⌉（在 5–15 之间；AI 换景不要搭景钱，可以比实拍宽松）；
- 叙事道具 ≤8 件；只出现一次的场景要写规避方案（能否并入已有场景）；
- 爽点间隔 ≤3 集，不能有真空区；第 1 集必须有钩子；大爆点不压在最后一集；
- 每集三栏齐全；三人以上同框要写拆解方案（AI 视频同框人数越多越容易崩）；
- 生成难点（大场面、水下、动物、复杂打斗）进「预警」清单。

## 输出

1. 改编说明：保留了什么、砍了什么、为什么、改编幅度；
2. 人物表：分档（主角组 / 重要配角 / 功能性）、人物线、原著出处（由谁合并而来）；
3. 爽点表：集号、爽点类型（打脸、逆袭、反转、揭秘、甜、虐…）、一句话内容；
4. 分集梗概：每集三栏 + 认领爽点；
5. 资产清单：从分集汇总的角色、场景、道具出场集数。

汇报时一句话说清：几集、几个角色几个场景、爽点分布、哪些门没过。
